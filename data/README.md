# 시장과 이야기 콘텐츠 데이터 초안

개발 중 작성해 보관한 고정 JSON 목록이다. 플레이 도중 AI에 글 생성을 요청하지 않고 목록에서 항목을 선택한다. 본문에 있는 `{company_name}`과 `{product_name}`만 해당 사건 회사의 값으로 치환한다. 현재 Unity MVP가 이 목록을 시장·피드에 연결하고, 실행 수치는 `Assets/Resources/GameConfig.asset`에서 읽는다. story는 첫 구간만 생활 진척 기준을 적용했고 장면은 아직 없다.

| 파일 | 항목 수 | 내용 |
| --- | --- | --- |
| companies.json | 12 | 회사명·종목명·업종·사업·제품 가칭 |
| events.json | 24 | 개발·출시·계약·실적·확장·심사·조달·협력 각 3개 결과 |
| news.json | 48 | 결과별 공식 기사와 후속 기사 |
| community_posts.json | 60 | 소문·사건 토론 32개, 일상·일반 토론·유머 28개 |
| community_comments.json | 96 | 사건 결과 반응 48개, 일반 반응 48개 |
| story_milestones.json | 4 | 구간별 선택지 2개가 있는 구조 초안 |

## 데이터와 난수의 관계

회사명과 종목명은 고정한다. 사건 종류·실제 결과·배정 종목·추세·등락 폭·정보 시각은 MVP의 회차 난수와 시장 규칙으로 정한다. 사실과 뉴스는 서로 연결한다. 상승·하락을 기사와 무관하게 매 순간 독립적으로 정하는 방식은 채택하지 않았다.

events의 `selection_weight: null`과 `return_magnitude: null`, 회사의 `initial_price: null`은 목록에서의 미정 값이다. null을 0으로 간주하거나 사건을 같은 확률로 자동 배정하지 않는다. MVP의 임시 사건 가중치·가격 영향·시작가는 GameConfig에 별도로 제공한다. `config/` JSON은 설정 에셋의 초기 가져오기용 자료다. 콘텐츠 수·문구 선택 가중치를 실제 호재 확률로 사용하지 않고, 임시값은 확정 밸런스와 구분한다.

뉴스와 게시글의 `selection_weight`는 유효한 후보가 여러 개일 때 문구를 선택하는 가중치 초안이다. `cooldown_sessions`는 사용한 항목의 중복을 줄이기 위한 대기 거래 세션 수이며, 미래 사건 공개를 앞당기는 값이 아니다. 처음 발생한 사건에 쓸 글이 모두 대기 중이면 표시 개수를 줄이는 것을 기본으로 한다. 임의로 과거 글을 새 기사로 다시 공개하지 않는다.

## 표시 조건

- `events.company_ids`: 사건을 배정할 수 있는 회사 목록이다. 업종에 따른 호환성 초안이다.
- `news.fact_tag`: 실제 사건 결과와 정확히 일치해야 한다. `publish_phase`도 해당 공개 단계여야 한다.
- `rumor_or_discussion` 게시글: 같은 topic의 여러 실제 결과에서 재사용한다. 이 글의 문구나 ID가 성공·실패 결과를 고정하지 않는다.
- `daily_or_general` 게시글: 특정 기업 사건의 증거가 아닌 일반 글이다.
- `community_comments.allowed_parent_ids`: 댓글이 달릴 수 있는 게시글 템플릿 ID 목록이다.
- `required_public_fact`: 해당 사건 인스턴스의 사실이 공개된 뒤에만 댓글을 사용할 수 있다. 과거 다른 회사 사건에서 같은 결과가 공개됐다는 이유로 미래 결과를 노출하지 않는다.
- `topic`, `fact_tag`, 사용 조건, 결과 목록은 내부 데이터다. 게임 화면에는 글·작성자·게시 시각·댓글 등 필요한 정보만 보여준다.

회사·사건·기사·댓글을 묶는 **회차 내 사건 인스턴스 ID**는 실행 시 별도로 필요하다. 이 목록의 사건 ID는 결과 유형 ID다. 결과 유형만 같고 서로 다른 회사·날짜인 사건을 한 사건으로 처리하지 않는다.

인스턴스에는 회사, 실제 결과, 예정 공개 시각, 이미 공개한 단계와 메시지, 해당 글에 붙은 댓글, 소문 복제 관계를 저장한다. 게시 시각은 시장 시각을 사용하고 PC의 실제 시각으로 결과를 바꾸지 않는다. 같은 게시글 재열람 시 새로운 댓글 추첨이나 숫자 재생성을 하지 않는다.

후속 기사는 공식 기사 이후에만 공개한다. 사건형 댓글은 같은 사건의 게시글에 붙이고, 일반 댓글도 `allowed_parent_ids`와 현재 문맥을 확인해 사용한다. 후보가 없으면 댓글을 줄인다.

조회 수·추천 수와 작성자 닉네임은 아직 별도 데이터로 준비하지 않았다. 추가할 때도 진실 여부와 단순 비례하게 만들지 않고, 회차에 표시한 값은 저장한다. 현재 기사·게시글 본문에 실제 금융 정보나 외부 글을 복사하지 않았다.

## 스토리 구간

생활 구간은 `life_progress_min`(생활 진척액)과 `cumulative_realized_net_profit_min`(누적 거래 실현 순손익)으로 판정한다. 첫 구간만 6만/1만 원을 적용했고, 나머지는 `draft_requirements`에 초안을 두고 `requirements`를 null로 유지한다. `scene_id`는 아직 미정이며, 하나라도 미정인 조건은 충족으로 간주하지 않는다. 앞 구간은 선택까지 마쳐야 다음 구간을 확인한다. 본편 대사와 장면 에셋도 아직 없다.

결산 후 순금융자산과 누적 거래 실현 순손익을 함께 확인하고, 앞 구간 진행 후 다음 구간으로 이동하는 구조다. 대출 입금은 수익으로 세지 않는다. 해금된 이야기와 선택은 해당 회차에서 유지하며, 컷신 갤러리 수집만 회차를 넘어 보존한다.

## 다음 콘텐츠 작성 기준

현재 204개 글 항목은 초기 분량이다. 같은 회사 이름만 치환한 것을 새로운 원고 수로 세지 않았다. 사건별 소문에 추가 변형을 붙이고, 생활 대화와 등장인물 성격을 확정한 뒤 원고를 확장한다. 장기 회차의 중복 빈도와 문구 암기 가능성은 아직 플레이 검증 전이다.

읽는 글 자체는 미리 준비하고, 이를 선택·배치하는 규칙만 무작위화한다. 단어를 맞춘 플레이어가 유리해지는 정답 문구나 결과 고정 닉네임을 피한다. `tools/validate_content_catalogs.py`로 문법·참조·치환의 기초 검증을 실행한다.
