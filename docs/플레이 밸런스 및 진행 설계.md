# MVP 플레이 밸런스와 진행 설계

버전 0.1 · 작성일 2026년 11월 25일

현재 Unity MVP를 기준으로 경제, 이야기 진입, 거래 시간, 복기, 아침 선택과 첫 플레이를 구체화한다. **현재값은 비교 기준으로 보존하고, 새 규칙은 다음 적용 초안으로 구분**한다. 이 문서 작성으로 게임 코드나 실행용 JSON 설정을 변경하지 않는다.

## 현재 MVP와 다음 적용 범위

Unity 버전 파일은 `6000.3.29f1`이다. 코드와 설정을 확인한 범위이며 실제 에디터 플레이·빌드 통과를 검증한 결과는 아니다.

| 영역 | 현재 코드와 설정에서 확인한 내용 | 다음 적용 초안 |
| --- | --- | --- |
| 하루 진행 | 집·알바·컴퓨터 앱·결산·컷신·다음 날 흐름 | 첫 15분의 단계별 안내와 7일 경험 검증 |
| 경제 | 시작 현금·급여·식사·가구·수수료·추가 대출 설정 | 아래 현재값을 기준으로 세 가지 플레이 시나리오 비교 |
| 시장 | 3종목, 180틱, 틱당 1.2초, 배속과 시장 일시정지 | 기본 거래 유지, 60틱 연장 1회 제안 |
| 스토리 | 구간 조건 판정과 선택 저장, 금액 조건과 장면 연결은 미정 | 일상 이야기와 생활 성장 장면의 개방 조건 분리 |
| 아침 | 근무 완료 또는 근무 건너뛰기 | 출근·휴식·상황별 만남으로 발전 |
| 복기 | 거래 기록·캔들·공개 글의 시각 데이터 존재 | 결산 뒤 과거 타임라인과 투자일지 표시 |
| 콘텐츠 | 뉴스·커뮤니티·댓글 목록과 시장 연결 코드 | 정보와 결과의 일관성, 중복 빈도 플레이 검증 |
| 코인·선물 | 주식 MVP에서 실제 거래 대상은 아님, 강제 청산 통계는 0 | 이번 7일 검증 이후 별도 설계 |

## 경제 수치와 첫 보상

### 현재 설정을 초기 비교 기준으로 채택

| 항목 | 현재값 | 설정 출처 |
| --- | --- | --- |
| 시작 현금 | 300,000원 | `config/balance.json` economy |
| 시작 부채 | 1,000,000,000원 | balance의 debt |
| 알바 1회 | 75초, 기본급 60,000원 | `config/job.json` |
| 근무 보너스 | 손님당 3,000원, 실수 감점 1,500원, 조건부 완벽 보너스 5,000원 | job |
| 매매 비용 | 매수·매도 각각 거래 금액의 0.1%, 매도세 0% | balance의 trading, 게임용 규칙 |
| 간식 | 2,000원, 컨디션 8 회복 | balance의 condition |
| 식사 | 9,000원, 25 회복, 60틱 동안 소모량 40% 감소 | condition |
| 에너지 음료 | 3,500원, 40틱 동안 소모 억제, 반복 효과 감소 | condition |
| 작은 화분 | 15,000원 | `config/shop.json` |

| 노트북과 모니터 | 150,000원 | shop |
| 추가 대출 | 현금 150,000원 미만일 때, 최대 원금 500,000원 | balance의 loan |
| 추가 대출 이자 | 하루 원금의 1%, 하루 최대 10,000원, 미상환 이자 누적 상한 100,000원 | loan, 게임용 규칙 |

이 표는 실제 금융 상품이나 임금의 설명이 아닌 게임 설정이다. 수치를 수정할 때는 실행용 JSON을 기준으로 이 표를 함께 갱신한다. 시작 부채와 추가 투자 대출은 별도 잔액으로 유지하고, 시작 부채에 추가 대출의 일일 이자를 그대로 적용하지 않는다. 현재 시작 부채에는 별도 이자 부과 코드가 없다.

### 초반 보상 목표

시작 현금만으로 작은 가구를 살 수 있는 현재 구성을 유지한다. 첫날 또는 둘째 날에 작은 구매를 경험할 수 있게 하고, 투자 원금을 남길지 지금 살지는 플레이어가 정한다. 구매를 첫 수익 이후로 잠그지 않는다. 기존의 첫 구매 2~3일 목표보다 현재 30만 원 시작값에 맞는 1~2일 목표를 우선한다.

첫날 이후 목표 화면에는 가구·첫 상환·투자 기록 중 하나를 선택해서 추적하게 하는 안을 제안한다. 이미 산 가구를 다시 요구하지 않고, 시작 부채를 아주 조금 갚아도 금액 변화와 캐릭터 반응을 보여준다. 매일 상환을 의무로 요구하지 않는다.

| 기간 | 경험 목표 | 보장 범위 |
| --- | --- | --- |
| 1~2일 | 앱 이동, 첫 거래 또는 관망, 첫 결산, 작은 구매 선택 | 조작 안내와 구매 기회 제공, 수익은 보장하지 않음 |
| 3~4일 | 소문과 기사 시각 비교, 거래 비용 이해, 상환 선택 | 실제 사건과 보유 기록에 맞는 반응 |
| 5~7일 | 다음 가구 목표, 재도전 또는 이익 확정, 서로 다른 밤의 반응 | 손실이어도 다음 날 근무 가능 |

### 세 가지 검증 시나리오

| 플레이 | 확인할 점 |
| --- | --- |
| 관망하며 일하는 플레이 | 투자하지 않아도 일상 이야기와 작은 생활 보상이 진행되는가 |
| 수익과 손실이 섞인 플레이 | 가구·음식·상환·재투자 중 선택할 이유가 있는가 |
| 첫날 투자 가능 현금을 잃은 플레이 | 다음 날 알바 기본급만으로 다시 주문할 수 있는가, 대출이 강요되지 않는가 |

검산용으로, 거래·대출·구매·상환·근무 보너스가 전혀 없고 7일 동안 기본급만 받은 경우 현금은 720,000원이다. 이때 매일 식사 9,000원만 추가 사용하면 657,000원이다. 이는 시장 수익의 예측이 아니라 입출금 기준선이다. 플레이 실측에서는 수수료·미실현 손익·상환·보너스를 구분한다.

### 전체 길이의 목표

첫 중간 결말과 주요 인물 서사는 우선 4~6시간 안에 한 흐름을 볼 수 있게 설계한다. 이 목표는 현재 MVP로 측정한 결과가 아니다. 7일 시제품에서는 첫 45~75분 정도의 경험을 검증한다. 배속 사용과 글 읽는 시간은 따로 기록한다.

10억 원 완전 상환은 별도의 장기 목표다. 초기 현금과 7일 경제를 그대로 늘린 것만으로 적정 클리어 시간이 확보됐다고 보지 않는다. 중후반 자금 규모·투자 대상 확장·사건 폭을 설계한 뒤 완전 상환 소요 시간을 검증한다. 특정 회차에 강제 대박을 넣어 목표 시간을 맞추지 않는다.

## 이야기 개방 조건

### 일상 이야기와 생활 성장 분리

프롤로그·주요 인물 대화·상실과 일상 회복의 이야기는 양수 순자산을 요구하지 않는다. 첫날 근무 완료 또는 건너뛰기, 첫 결산, 특정 인물의 앞 대화 감상처럼 실제 진행 조건으로 연다. 거래하지 않은 경로와 손실 경로에도 맞는 대사를 제공한다.

처음에는 첫 결산 후 짧은 일상 장면, 3일차 아침에 점장과의 후속 대화를 배치하는 안으로 잡는다. 이는 장편 전체를 날짜만으로 자동 진행한다는 뜻이 아니다. 다음 장의 필수 장면과 인물 소개를 순서대로 확인하고, 해당 투자 사건이 없으면 일상·주변 인물 경험으로 변형한다.

생활 성장 장면은 자금과 투자 성과를 조건으로 한다. 다음 기준은 현재 실행용 `data/story_milestones.json`에 아직 적용하지 않은 제안이다.

### 생활 성장용 기준 금액

시작 부채를 제외한 **생활 순자금 = 현금 + 보유 현물 평가액 − 추가 투자 대출의 원금·발생 이자**로 정의한다. 시작 부채 10억을 포함한 순금융자산도 금융 화면에 계속 표시한다.

가구 구매와 시작 부채 상환이 성장을 지우지 않도록 **생활 진척액 = 생활 순자금 + 누적 가구 구매액 + 시작 부채 누적 상환액 − 회차 시작 현금**을 별도로 기록하는 안을 채택한다. 시작 무료 가구는 0원이며, 실제 지불한 금액만 한 번 더한다. 식사와 이자는 비용으로 남는다.

예를 들어 대출만 받으면 현금과 추가 부채가 같은 만큼 늘어 진척액은 그대로다. 시작 부채를 상환하면 현금은 줄지만 누적 상환액이 늘어 진척액이 유지된다. 새 가구를 사도 같은 방식으로 보존된다. 초기 30만 원을 그대로 소비한 것만으로는 추가 성장으로 계산되지 않는다.

| 생활 성장 구간 | 진척액 하한 초안 | 누적 거래 실현 순손익 하한 | 장면 방향 |
| --- | --- | --- | --- |
| 처음 생긴 여유 | 60,000원 | 10,000원 | 작은 개선과 다음 목표 중 선택 |
| 자리를 잡은 일상 | 250,000원 | 50,000원 | 익숙한 공간과 새로운 생활 중 선택 |
| 넓어진 선택지 | 1,000,000원 | 300,000원 | 사람과의 시간과 더 큰 목표 중 선택 |
| 내가 선택한 성공 | 3,000,000원 | 1,000,000원 | 개인 생활 목표를 확인하는 장면 |

이 금액은 생활 장면의 기준이며 10억 완전 상환 엔딩 조건이 아니다. 각 구간의 이전 선택을 완료해야 다음 구간이 열린다. 조건 달성 시점을 기록하고 이후 손실로 이미 연 구간을 취소하지 않는다. 하루에 새 주요 구간은 하나씩 진행한다.

현재 코드에는 생활 진척액 통계가 없고, story JSON의 조건은 null이다. 적용하려면 회차 시작 현금·시작 부채 원금 기준·누적 지출과 상환 기록을 저장하고, 판정 통계와 검증 도구를 함께 추가해야 한다. 이 문서의 금액을 현재 `net_financial_assets_min`에 그대로 넣지 않는다.

## 기본 거래와 연장 거래

현재 MVP는 21:00~24:00에 해당하는 180틱 세션이다. 1배속에서 180×1.2초=216초, 약 3분 36초다. 2배속은 약 1분 48초, 4배속은 약 54초이며 읽기·메뉴 정지 시간은 제외한 값이다. 현물은 다음 날로 보유할 수 있고 연장 거래는 아직 없다.

다음 적용은 **180틱 기본 거래 + 선택형 60틱 연장 1회**로 잡는다. 연장은 기본 마감 전에 제안하고, 선택하면 게임 시각 01:00까지 72초를 더 거래한다. 선택하지 않으면 기존 마감으로 끝난다. 연장을 선택해도 언제든 조기 결산할 수 있다.

기본 틱당 컨디션 소모는 현재 0.3을 비교 기준으로 유지하고, 연장 구간은 0.45를 초안으로 둔다. 잠을 자면 100으로 회복하며, 근무 시 10 소모를 반영한다. 회복 수단 없이 기본 세션을 모두 보면 100−10−180×0.3=36이고, 연장까지 모두 진행하면 9가 된다. 따라서 기본 거래는 완료 가능하지만, 오래 버틸수록 관찰 방해가 커진다.

식사는 현재의 회복과 소모 완화, 음료는 현재의 일시 소모 억제 역할을 유지한다. 음료는 소진된 컨디션을 직접 회복하지 않으므로 0에서 다시 거래하려면 식사·간식 또는 밤 종료를 고르게 한다. 회복 메뉴는 시장을 멈추며, 아이템을 썼다는 이유로 세션 길이가 자동 연장되지는 않는다.

연장 가능 구간의 사건과 가격 난수도 회차 규칙에 따라 준비한다. 연장 버튼을 누르는 순간 유리한 사건을 다시 추첨하거나 미래 결과를 먼저 보여주지 않는다. 연장하지 않은 구간을 실제로 관측한 것처럼 복기에 표시하지 않는다. 다음 날 첫 가격은 실제 마지막으로 진행한 시장 가격에서 이어진다. 세션 길이를 바꾸는 일이므로 기존 저장과 다음 날 사건 일정까지 검증한 뒤 코드에 적용한다.

## 투자 복기와 일지

복기는 결산에서 선택해 볼 수 있는 화면으로 추가한다. 긴 의무 절차로 만들지 않고, 집 컴퓨터의 투자일지에서도 지난 기록을 연다. 증권 앱 본 화면에는 복기 패널을 상시 붙이지 않는다.

| 표시 | 내용 |
| --- | --- |
| 과거 차트 | 해당 밤 실제 진행한 캔들, 종목 선택 |
| 매매 위치 | 매수·매도 시각, 수량, 가격과 수수료 |
| 공개 정보 | 그 시점에 공개됐던 소문·공식 기사·정정과 열람 여부 |
| 결과 | 실현 손익과 남은 보유분의 평가 손익 구분 |
| 선택 메모 | 플레이어가 원하면 매매 이유 한 줄 기록 |

복기는 일반 플레이어에게 이미 공개된 정보만 보여준다. 미래 뉴스, 아직 밝혀지지 않은 사건의 실제 결과, 내부 시드와 호재 확률은 노출하지 않는다. 플레이어가 읽지 않았더라도 공개돼 있었던 글은 그 사실을 구분해서 볼 수 있다. 지나간 특정 시점으로 옮겨 볼 때도 그 시점 이후의 정보는 접어 둔다.

수익·손실만으로 좋은 판단과 나쁜 판단을 채점하지 않는다. “호재 뉴스 공개 뒤 진입해 손실 확정”처럼 확인된 기록을 표시하고, 손실의 원인을 하나의 뉴스로 단정하지 않는다. 글을 읽었거나 매수했다는 이유만으로 심리 상태를 확정하지 않는다.

기존 `TradeRecord`·캔들·`FeedItem`에 기본 자료가 있으나 복기 화면은 아직 없다. 이후 콘텐츠 양이 늘어도 과거 글·차트가 사라지지 않게 회차 기록 보관 범위와 저장 크기를 함께 검토한다.

## 성장 이후의 아침

아침 선택은 출근·휴식·상황별 만남으로 확장한다. 거래 성과가 낮아도 일상 이야기를 볼 수 있고, 자금이 충분해지면 급여와 시간의 우선순위를 바꿀 수 있게 한다.

| 선택 | 수입과 컨디션 초안 | 역할 |
| --- | --- | --- |
| 출근 | 현재 75초 근무와 기본급·보너스, 컨디션 10 소모 | 안정적인 수입과 편의점 일상 |
| 휴식 | 수입 없음, 기본 수면 회복 상태를 보존 | 미니게임 없이 다음 저녁으로 이동 |
| 만남 | 수입 없음, 근무 피로 없음, 예정된 짧은 대화 | 인물 서사와 관계 변화 |

휴식은 매일 선택 가능하게 하고, 만남은 앞 장면과 상황 조건이 맞을 때만 표시한다. 만남을 선택하면 그날 출근은 하지 않은 것으로 처리한다. 같은 날 근무와 휴식·만남을 반복해 수입이나 회복을 중복 획득하지 않는다.

투자 규모가 커졌다는 이유로 알바 급여를 자동으로 올리거나 출근을 계속 강제하지 않는다. 출근을 그만두는 선택을 정식 엔딩 뒤에 검토하되, 첫 7일에는 복잡한 퇴사·재취업 시스템을 추가하지 않는다. 현재의 `SkipJob`은 휴식의 기본 동작이며, 인물 만남은 별도 구현이 필요하다.

## 첫 15분의 진행안

시간은 1배속과 안내를 읽는 첫 플레이 기준의 목표다. 빨리 읽거나 관망하는 플레이어에게 같은 시간을 강요하지 않는다.

| 실제 경과 목표 | 진행 | 확인할 경험 |
| --- | --- | --- |
| 0~2분 | 작은 방, 오늘 할 일, 시작 부채와 현금 확인 | 무엇을 위해 일하고 투자하는지 이해 |
| 2~4분 | 편의점 조작 안내와 첫 75초 근무 | 기본급을 직접 벌고 투자금과 연결 |
| 4~6분 | 컴퓨터 바탕화면, 브라우저의 기사와 글 각 1개 | 앱 분리와 정보 시각 이해 |
| 6~10분 | 증권 앱, 진행·정지, 수량과 비용, 직접 매매 또는 관망 | 주문을 이해하고 스스로 선택 |
| 10~12분 | 첫 결산, 선택형 상환, 실제 결과에 맞는 짧은 반응 | 손익·부채·소비의 차이 이해 |
| 12~15분 | 작은 가구 구매 또는 보류, 다음 날과 다음 목표 | 한 번 더 진행하고 싶은 이유 형성 |

진행 중인 시장 위에 긴 안내를 띄우지 않는다. 처음 보는 거래 안내는 정지 상태에서 보여주고, 명시적으로 재개한 뒤 시장이 움직이게 하는 방향으로 잡는다. 튜토리얼 재열람은 가능하게 한다.

첫 수익과 특정 종목의 상승을 보장하지 않는다. 첫날 손실이면 다음 날 근무와 자금 복귀를 안내하고, 관망이면 선택을 존중하는 대사를 보여준다. 정보와 주문을 이해시키기 위한 안내가 정답 종목 추천이 되어서는 안 된다.

현재 앱별 설명 튜토리얼은 있지만 이 표의 순차 안내와 목표 추적은 아직 없다. 첫 검증에서는 UI 문구·클릭 순서·실제 소요 시간을 기록해 어디서 멈추는지 찾는다.

## 다음 적용 순서와 완료 기준

1. **현재 MVP로 7일 플레이 확인:** 화면 전환·돈 계산·식사 효과·상환·컷신·저장 복구를 실제로 검증하고 초기 비교값 기록.
2. **첫날 안내와 첫 생활 이야기:** 거래를 강요하지 않는 안내와 결과별 첫 결산 반응 연결.
3. **생활 진척 통계와 첫 구간:** 우선 첫 구간 1개를 적용하고 대출·구매·상환이 지표를 왜곡하지 않는지 확인.
4. **결산 복기 화면:** 기존 기록을 이용해 한 종목의 공개 정보와 주문 위치부터 보여주기.
5. **거래 연장과 아침 만남:** 시장 일정·컨디션·저장 구조의 영향이 커 앞 단계 검증 후 적용.

| 기준 | 통과 조건 |
| --- | --- |
| 첫 플레이 이해 | 도움 없이 컴퓨터·브라우저·증권 앱을 오가며 수량과 비용을 설명할 수 있음 |
| 복귀 | 현금 소진 후 다음 날 근무로 다시 매매 가능 |
| 이야기 | 수익이 없어도 첫 일상 장면 진입, 투자 성장 구간은 조건을 갖추고 진입 |
| 자금 계산 | 대출 입금만으로 진척이 늘지 않음, 구매와 시작 부채 상환은 기존 진척을 보존 |
| 정보 | 소문·기사·매매·정정의 시각이 일관되며 복기에 미래 사실이 나오지 않음 |
| 컨디션 | 관찰 방해와 회복 수단의 차이가 느껴지고 주문 정보는 정확함 |
| 다음 날 동기 | 다음 이야기·가구·상환·거래 기회 중 스스로 다음 목표를 말할 수 있음 |

아직 구현되지 않은 항목의 검증을 통과로 표시하지 않는다. 문서의 적용 초안을 코드에 반영할 때는 `config/`, 판정 통계, 저장 데이터, 설명과 검증 도구를 함께 갱신한다.
