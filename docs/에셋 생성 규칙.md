# 일러스트와 게임 에셋 생성 규칙

버전 1.0 · 작성일 2026년 11월 25일

Unity 기반 2D 주식 게임의 일러스트와 이미지 에셋을 제작·생성·다운로드할 때 적용한다. 최종 목표는 Steam 출시다. **화면 배치는 FHD 기준, 배경과 컷신 원본은 4K 목표, 실제 사용 이미지는 용도별로 분리**한다.

이 문서의 해상도는 제작 목표다. 생성 도구의 실제 출력이 목표보다 작으면 원본 크기를 그대로 기록하고, 확대본과 구분한다. 현재 단계는 컨셉 기획이며, 아래 규칙을 정한 것이 Unity 임포트나 최종 아트 승인을 의미하지는 않는다.

## 공통 아트 방향

- 캐릭터·배경·소품·컷신·OS 그래픽은 밝고 부드러운 파스텔 톤을 지향한다.
- 우윳빛 흰색과 옅은 하늘색을 바탕으로 민트·연보라·연분홍을 보조색으로 사용한다. 구체적인 색상표는 후속 시안에서 확정한다.
- 밤은 부드러운 푸른 그림자와 따뜻한 실내 조명으로 표현한다. 어두운 장면에서도 얼굴·손·주요 소품이 읽혀야 한다.
- 캐릭터의 선화·얼굴 비율·머리카락 표현은 승인된 캐릭터 시트에 맞춘다. 파스텔 톤으로 바꾸는 과정에서 얼굴이나 그림체를 임의로 바꾸지 않는다.
- 블루 아카이브는 색감과 분위기의 참고다. 이 프로젝트의 인물·로고·아이콘·OS·앱 화면은 독자적으로 설계한다.
- 기존 컨셉 이미지가 여러 개 있으면 이번 작업에 사용할 버전과 참고 요소를 먼저 지정한다. 최신 파일이라는 이유만으로 모든 요소를 확정 기준으로 삼지 않는다.

## 화면 기준과 해상도

기본 UI 설계 해상도는 **1920×1080, 화면 비율은 16:9**로 잡는다. 2560×1440과 3840×2160에서도 배치와 글자 크기를 확인한다. 다른 화면 비율에서는 UI를 늘려 찌그러뜨리기보다 앵커·여백·필요한 배경 확장으로 대응한다.

| 종류 | 권장 원본 목표 | 생성 및 분리 기준 |
| --- | --- | --- |
| 집·편의점·기타 전체 배경 | 3840×2160 | 16:9, 중요 인물·물건을 가장자리에 밀착하지 않음 |
| 전체 화면 컷신 | 3840×2160 | 얼굴 확대·카메라 이동을 고려해 구도와 주변 여유 확보 |
| OS 바탕화면 배경 이미지 | 3840×2160 | 창·작업 표시줄·아이콘·문자를 그려 넣지 않은 배경 |
| 캐릭터 입상 | 2048×3072 전후 | 세로형, 투명 배경, 머리카락·손·의상 끝이 잘리지 않게 제작 |
| 표정·의상·컨디션 변형 | 기준 입상과 동일 | 캔버스·몸 위치·얼굴 기준점·배율 통일 |
| 대형 가구·전경 소품 | 긴 변 1024~2048px | 교체할 물건은 배경과 분리, 장면의 원근과 조명 일치 |
| 음식·음료·작은 소품 | 512×512 또는 긴 변 1024px | 화면에서 차지하는 크기에 따라 결정, 투명 배경 |
| 바탕화면 앱 아이콘 | 512×512 | 같은 여백과 시각적 크기, 작은 표시 크기에서도 구별 가능 |
| 상태·작은 기능 아이콘 | 128×128 또는 256×256 | 단순한 실루엣, 필요하면 코드·벡터 형태 우선 검토 |
| 창·버튼·패널 장식 | 용도별 결정 | 단순 면·테두리는 Unity에서 구성하고 반복되는 테두리는 늘려 쓸 수 있게 분리 |

4K는 전체 화면 이미지의 보관 원본 목표이며 모든 작은 에셋의 규격이 아니다. 최종 사용 크기와 최대 확대 배율을 기준으로 정한다. 예를 들어 화면에서 높이 900px인 인물을 2배까지 확대할 예정이면, 실제 인물 그림의 높이는 최소 1800px 이상을 목표로 한다. 투명 여백을 포함한 캔버스 높이만으로 충분한 디테일이 있다고 판단하지 않는다.

생성 도구가 정확한 비율이나 해상도를 지원하지 않으면 가장 가까운 출력을 선택하고 안전 여백을 확보한다. 원본을 보존한 뒤 잘라내기·여백 확장·확대를 별도 파생본으로 기록한다. 목표에 맞추려고 그림을 가로 또는 세로로 찌그러뜨리지 않는다. 단순 확대본을 실제 4K 디테일의 원본이라고 표기하지 않는다.

## 컨셉 이미지와 실제 게임 에셋

컨셉 이미지는 구도·분위기·화면 흐름을 확인하기 위한 자료다. 인물·방·모니터·글자가 합쳐진 컨셉 한 장을 그대로 실행 가능한 게임 화면으로 사용하지 않는다.

| 이미지로 제작할 요소 | Unity에서 구성할 요소 |
| --- | --- |
| 방·편의점 배경과 별도 소품 | 클릭 영역과 화면 전환 |
| 캐릭터·표정·손·의상 | 대사창과 실제 대사 텍스트 |
| 바탕화면 배경과 독자적인 앱 아이콘 | 앱 창·작업 표시줄·열기·닫기·최소화 |
| 필요한 장식과 효과 이미지 | 차트·거래량·가격·잔액·주문 정보 |
| 컷신 인물과 배경 | 뉴스·커뮤니티 글·댓글·시간·수집률 |

실제 주가·계좌 숫자·회사명·뉴스·버튼 문구는 생성 이미지에 굽지 않고 UI 텍스트로 표시한다. 폰트는 별도로 확인한 라이선스를 따르며, 생성 이미지의 글자가 해당 폰트를 정식 적용한 것이라고 기록하지 않는다.

증권·인터넷·금융·앨범은 역할이 다른 앱으로 유지한다. 화면 컨셉을 생성할 때도 각 앱을 따로 요청하고, 모든 기능을 한 투자 창에 다시 합치지 않는다.

## 캐릭터와 장면의 일관성

캐릭터 기본 시트에는 정면·측면의 특징, 머리·눈 색상, 의상, 주요 장신구와 비율을 기록한다. 이후 표정·포즈·컷신은 해당 시트를 참고한다. 현재 확정되지 않은 외형을 생성 과정에서 임의로 공식 설정으로 만들지 않는다.

표정 교체용 이미지는 같은 크기의 캔버스에서 머리와 몸의 기준점을 유지한다. 얼굴 부분만 교체한다면 기준 얼굴의 위치와 크기, 목·머리카락 경계도 맞춘다. 크롭하거나 여백을 제거할 때는 기준점 변환을 기록한다.

방과 가구는 같은 카메라 각도·바닥선·광원 방향을 따른다. 교체 가능한 책상·의자·모니터·음식은 별도 이미지로 만든다. 캐릭터가 물건을 잡거나 가리는 장면은 필요한 경우 뒤 배경·물건·몸·앞쪽 손처럼 겹침 순서를 나눈다. 모든 장면을 불필요하게 세분화하지 않고, 실제로 움직이거나 교체할 요소부터 분리한다.

컷신에서 카메라 이동이나 표정 변화가 필요하면 인물·배경·전경·표정 등을 분리한다. 정적인 감상 장면은 합성본도 함께 보관할 수 있다. 모션을 붙일 레이어를 잘린 가장자리에서 끝내지 않는다.

## 파일 형식과 폴더

- 원본 출력과 작업 가능한 레이어 파일이 있으면 모두 보존한다. 레이어 작업 원본과 게임용 출력은 구분한다.
- 인물·소품·아이콘은 알파 채널이 있는 PNG로 출력한다. 투명 배경 요청 시 체크무늬를 실제 배경으로 그린 파일을 사용하지 않는다.
- 배경·컷신 보관본도 PNG를 우선한다. JPEG만 제공된 원본은 그대로 보관하고, PNG로 변환했다고 손실 전 원본이 복원됐다고 간주하지 않는다.
- 색상 작업은 sRGB 기준으로 맞추고, 화면 확인 없이 색상 프로파일을 임의 변경하지 않는다. 화면 에셋은 DPI보다 실제 픽셀 수를 기준으로 관리한다.

| 경로 | 용도 |
| --- | --- |
| `docs/concepts/` | 화면과 구도 검토용 컨셉 이미지 |
| `docs/previews/` | 축소·합성·실제 크기 비교 미리보기 |
| `ThirdParty/Generated/<AssetID>/` | 이후 AI 생성물의 최초 출력, 프롬프트, 참조 목록, 제작 기록 |
| `ThirdParty/<종류>/<AssetID>/` | 다운로드 원본, 공식 이용 조건, 출처 증빙 |
| `Assets/Art/Backgrounds/` | 게임용 배경 |
| `Assets/Art/Characters/` | 캐릭터와 표정·의상 |
| `Assets/Art/Cutscenes/` | 컷신용 이미지 |
| `Assets/Art/Props/` | 가구·음식·음료·소품 |
| `Assets/Art/UI/` | UI 아이콘·장식·배경화면 |

기존에 다른 경로로 기록한 원본은 이 규칙 때문에 이동하거나 덮어쓰지 않는다. 새 관리대장 항목에 실제 위치를 연결한다. 원본 ZIP·프롬프트·증빙 페이지를 게임의 Assets 안에 무분별하게 넣지 않는다.

## 파일명과 버전

파일명은 영문 소문자·숫자·밑줄로 통일하고, 의미 있는 상태와 버전을 붙인다. 승인된 파일을 새 결과로 덮어쓰지 않는다.

```text
bg_home_stage01_night_v001.png
chr_protagonist_default_neutral_v001.png
chr_protagonist_default_tired_v001.png
prop_energy_drink_blue_v001.png
ui_icon_browser_v001.png
cg_first_profit_character_v001.png
cg_first_profit_background_v001.png
```

확대본에는 `_upscaled`, 실제 게임용 크기로 줄인 파일에는 `_runtime` 등 파생 상태를 추가한다. 정확한 크기와 변환 방법은 제작 기록에도 남긴다. 컨셉 검토 중의 결과에는 승인·확정 의미의 이름을 임의로 붙이지 않는다.

## 생성 요청과 출처 기록

생성 전에 용도, 참고 이미지, 목표 크기, 화면 비율, 배경 투명 여부, 분리 요소와 유지할 특징을 정한다. 재현에 필요한 요청은 아래 양식으로 원본 폴더에 보관한다.

```yaml
asset_id: ART-0001
status: concept
purpose: 집의 야간 배경
target_size_px: [3840, 2160]
actual_generated_size_px: 미기록
runtime_size_px: 미정
aspect_ratio: "16:9"
transparent_background: false
tool_and_model: 미기록
created_at: 미기록
reference_files_and_ids: []
prompt_file: prompt.txt
original_file: generated-original.png
derived_files: []
transformations: []
original_sha256: 미기록
rights_and_terms_evidence: 미확인
review_notes: 검토 전
```

프롬프트에는 이번 작업의 선화·채색·조명·구도·분리 레이어·불필요한 문자나 UI를 포함하지 않는 조건을 구체적으로 적는다. 사용 도구가 기록해 주지 않는 모델명·시드·설정을 추정해 채워 넣지 않는다. 수정 생성에서는 편집 대상과 참고 이미지의 역할을 각각 기록한다.

무료 다운로드 여부와 별도로 상업용 게임 사용·재배포·수정·고지 조건을 확인한다. AI 생성물도 도구와 확인 당시 약관, 참고 이미지의 출처·이용 가능 범위를 기록한다. 자체 생성했다는 사실만으로 참고 이미지의 권리 문제가 해결됐다고 처리하지 않는다.

모든 채택 후보를 [리소스 관리대장](리소스%20관리대장.md)에 등록한다. 외부 리소스의 이용 조건에 필요한 고지는 `THIRD_PARTY_NOTICES.txt`에 반영한다. 컨셉 참고 자료와 실제 출시용으로 채택한 파일은 구분해서 표시한다.

## Unity 적용과 확인

보관 원본과 게임에서 사용하는 텍스처 크기는 구분한다. 원본은 유지하고 Unity 임포트 설정에서 크기·압축을 조절한다. 3840×2160 이미지를 실제 4K로 사용할 때는 Max Size가 이를 줄이지 않는지 확인한다. 세부 설정은 실제 Unity 버전과 에셋 용도에 맞춰 정한다.

UI는 FHD 기준으로 배치하되 해상도 변화에 맞게 조절한다. 창 크기와 문자열 길이가 달라져도 버튼·가격·기사가 잘리지 않는지 확인한다. 숫자와 본문은 별도 폰트 UI로 유지한다.

화면에 붙는 2D UI는 밉맵 불필요 여부, 일러스트는 필터·압축 후 선화와 그라데이션 손상을 확인한다. 읽기·쓰기 가능한 텍스처가 필요한지도 용도에 따라 확인한다. 모든 에셋을 같은 임포트 설정으로 일괄 확정하지 않는다.

- [Unity Canvas Scaler 공식 문서](https://github.com/Unity-Technologies/uGUI/blob/main/com.unity.ugui/Documentation~/script-CanvasScaler.md)
- [Unity 텍스처 크기와 플랫폼별 설정 공식 문서](https://docs.unity.com/en-us/engine/6000.6/manual/materials-and-shaders/textures/textures-reference/class-texture-importer/type-specific)

## 채택 전 확인 목록

- [ ] 실제 픽셀 크기와 목표 크기를 구분해 기록했다.
- [ ] 파스텔 색감과 캐릭터 기준 시트, 장면의 원근·광원이 맞는다.
- [ ] 머리·손·소품 끝이 잘리지 않고 손가락·얼굴·물건 구조를 확인했다.
- [ ] 투명 영역에 체크무늬·배경 잔여물·밝은 테두리가 없다.
- [ ] 교체·클릭·애니메이션이 필요한 요소가 분리되어 있다.
- [ ] 실제 UI 글자·숫자·차트를 그림에 합쳐 넣지 않았다.
- [ ] 축소한 실제 표시 크기와 최대 확대 상태에서 모두 확인했다.
